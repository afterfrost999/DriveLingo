# 정책 검토 (승인·확인이 필요한 항목)

공식 문서 기준으로 검토했습니다. "미승인" 항목은 프로토타입에 구현은 되어 있지만, 실제 배포 전에 Pleos와 협의해야 합니다.

## 1. 앱 카테고리: Music/Audio 적합성 — 판단 보류, 협의 필요

| 문서 요구사항 | 말차 현황 |
|---|---|
| 오디오 콘텐츠 재생이 앱의 **주 기능**이어야 함 | 핵심은 **말하기(마이크) 대화**입니다. 오디오를 듣는 것은 절반에 그칩니다 |
| 하위 카테고리(음악/팟캐스트/오디오북/라디오) 정의 필수 | 어느 하위 카테고리에도 딱 맞지 않습니다. 굳이 고르면 팟캐스트·오디오북에 가깝습니다 |
| MediaBrowserService(MBS) + MediaSession **필수** (미구현 시 심사 통과 불가) | 구현(`feature/media/`). 탐색 트리는 "오늘의 수업" 하나입니다 |
| 스티어링 휠 키(재생/일시정지/정지 등) 지원 필수 | 구현. 재생=재개(없으면 새 수업), 일시정지, 이전=다시 듣기, 정지=중단 지점 저장 |
| 연결 시 자동 재생 금지 | 기본 동작은 준수합니다(아래 2번) |

- 문서의 카테고리 목록에는 Music/Audio 말고도 Lifestyle, Business 등이 있습니다. 다만 "주행 중 기능이 제한적으로 허용될 수 있는 카테고리"로 문서가 예시를 든 것은 **Music/Audio, Maps/Navigation, Mobility Services**뿐입니다.
- 주행 중에 쓰는 것이 핵심인 앱이라 Music/Audio로 신청하는 것이 현실적인 선택지입니다. 그러려면 다음 두 가지가 필요합니다.
  1. (구현) 수업을 MBS/MediaSession 기반 "오디오 레슨"으로 노출하고, 스티어링 휠 재생·일시정지 버튼에 수업 일시정지·재개를 연결합니다.
  2. (**미승인**) 마이크로 대화하는 기능이 Music/Audio 범위로 인정되는지 Pleos 사전 협의로 확인합니다.
- 남은 일: 앱 화면 없이 미디어 화면에서만 오래 재생하려면 `mediaPlayback` 포그라운드 서비스가 필요합니다. 지금은 앱 프로세스가 살아 있는 동안만 미디어 세션이 동작합니다.
- 미디어 화면은 주행 중에도 보이므로, 미디어 세션 부제에는 상태("듣는 중", "잠시 멈춤 · 전화")만 넣습니다. 학습 문장·점수·숫자는 넣지 않습니다(단위 테스트로 확인).
- 매니페스트에는 `android:appCategory="audio"`를 임시로 선언해 두었습니다.

## 2. 자동 재생 정책 — 시동 안내와 실제 음성 재생을 분리했습니다

문서 근거:
- "앱 연결 시 자동 재생은 금지하며, 사용자의 명시적 동작 또는 시스템 재개 요청에 따라 재생해야 합니다."
- "프로필이 변경된 경우에도 음원을 자동 재생하면 안 됩니다."

구현 내용:
- **시동을 걸면 화면 안내만 합니다.** 홈 화면은 텍스트로만 오늘 수업을 안내하고 소리를 내지 않습니다.
- **음성 재생은 사용자가 시작 버튼을 누를 때만 시작합니다.** 시작할 때 오디오 포커스를 요청합니다.
- 시안의 "그냥 출발해도 자동으로 시작해요"는 설정 화면의 **"출발하면 자동으로 시작"(기본 꺼짐)** 옵션으로 옮겼습니다. 사용자가 직접 켠 경우에만 출발(주차 → 주행 전환) 시점에 수업을 시작합니다. 문구도 켜고 끔에 따라 바뀝니다.
- **미승인**: 사용자가 미리 동의해 둔 경우라도 "출발 시 자동 시작"이 "명시적 동작"으로 인정되는지 문서만으로는 판단할 수 없습니다. 협의 전까지는 기본값을 꺼 둡니다.
- 오디오 포커스를 영구 상실(`AUDIOFOCUS_LOSS`)한 뒤에는 자동으로 재개하지 않습니다. 사용자가 재생 버튼을 눌러야 포커스를 다시 요청합니다.
- 운전대 재생 버튼으로 수업을 시작하는 것은 사용자의 명시적 동작으로 봅니다. 일시정지·이전·정지 버튼은 수업을 시작하지 않습니다.
- **미승인 퍼미션**: `pleos.car.permission.CAR_LIGHTS`·`CAR_DRIVE`·`CAR_SAFETY`(Vehicle SDK), `STT_SERVICE`·`TTS_SERVICE`를 매니페스트에 선언했습니다. 배포 전에 Pleos App Market과 승인 범위를 협의해야 합니다.

## 3. 주행 중 화면 제한 — CarUxRestrictions 기준

- 속도 0 여부가 아니라 `CarUxRestrictions.isRequiresDistractionOptimization()`으로 화면 제한을 판단합니다(`DrivingStatus.uiRestricted`). 값을 모르면 제한으로 봅니다.
- 주행 중에는 다음처럼 제한합니다.
  - 홈: 숫자·랭킹·코스 링크를 숨기고, 제목과 큰 시작 버튼만 남깁니다.
  - 수업: 큰 상태 표시, 일시정지·다시 듣기 버튼만 둡니다. 음성 전사(내 말 텍스트)는 표시하지 않습니다(`NO_VOICE_TRANSCRIPTION`).
  - 코스·설정·레벨 테스트: "주차 후" 안내로 막습니다(`NO_SETUP` 성격).
  - 리포트: 큰 숫자 2개만 보여 줍니다(`LIMIT_CONTENT`).
- 반복 애니메이션은 쓰지 않습니다. 진행 링이 바뀔 때만 0.6초 동안 보간합니다.
- **미승인**: 주행 중에 쓰려면 `distractionOptimized` 메타데이터를 선언해야 하고, DO 허용 여부는 심사 대상입니다.

## 4. 개인정보

- 음성 원본: 저장하거나 전송하지 않습니다. STT 결과 텍스트도 리포트의 "교정된 표현"(최근 20개)만 기기에 남깁니다.
- 위치 원본: 저장하거나 전송하지 않습니다. 랭킹은 "구간 이름 + 주간 단어 수"만 다루고, **명시적으로 참여(opt-in)한 사용자만** 대상으로 합니다. 기본값은 꺼짐입니다.
- 운행 기록: 운전한 "날짜"만 남깁니다(스트릭 판단용). 거리·속도·주행 시간은 기록하지 않습니다.
- 비밀정보: LLM API 키와 STT/TTS Client Secret은 앱에 넣지 않습니다(백엔드에서 처리).
